# FIRE Planner

Offline, single-file HTML FIRE (Financial Independence, Retire Early) calculators for a couple (or single person). Nothing leaves your device — open the file in a browser and it runs entirely client-side, with no server, account, or internet connection required.

MIT licensed — see [LICENSE](LICENSE).

## Files

- `index.html` — landing page linking to both tools
- `Planner_US.html` — US version
- `Planner_Canada.html` — Canada version (Ontario / BC)
- `CLAUDE.md` — architecture notes and gotchas for Claude Code (or any AI assistant) working in this repo

## Shared capabilities

Both tools run on the same underlying engine and share these features:

- **Guided setup wizard**: an optional 2-step modal, launched from the prominent "✨ Get started" button in the topbar, for getting a first projection running — step 1 asks for the basics (single/partnered, ages, income, retirement age, account balances, spending). Step 2, "A few optional questions," groups the features below by everyday category (Healthcare, Income, Taxes & investing, Guardrails, Debt) rather than one flat checklist, so a novice sees a short, organized set of things to skip rather than eight sophisticated concepts in a row: Healthcare (ACA subsidy, long-term care), Income (part-time income, additional income), Taxes & investing (Roth conversion/RRSP meltdown ladder, mega backdoor Roth), Guardrails (Guyton-Klinger), and Debt (other loans). Every wizard field is a live proxy for the real sidebar control, so it never gets out of sync and can be safely skipped entirely. Every field spells out what it does and doesn't cover — income is explicitly gross/pre-tax, the account-balance fields are explicitly combined totals across every account of that type, household spending explicitly excludes housing and healthcare (which have their own fields later, already pre-filled with placeholders), and each step-2 checkbox explains what turning it on actually changes, not just where its section lives. A ✕ button in the corner (in addition to Escape or clicking outside the modal) closes the wizard from either step without leaving the page — useful since a phone's or browser's own back button would otherwise navigate away from the tool entirely rather than just closing the dialog
- **First-run banner**: sits above the two-column assumptions/results layout (not inside either side), so it's visible immediately on load and, on mobile, on both the Inputs and Dashboard tabs without switching. It spells out that the loaded numbers are a generic example, not yours, and points at the two ways to fix that (the setup wizard, or importing a previously-exported scenario file); it clears itself the moment either happens, or the moment you edit any sidebar field directly.
- **"What do you want to figure out?" menu**: a small, collapsed-by-default "💡 What do you want to figure out?" bubble right under the plan verdict — click it to expand the full menu in place, rather than a big menu competing with the verdict for attention or getting buried at the bottom of a long page. Only appears on the Dashboard tab (it's part of the results). Each of the eight questions is now a bigger, card-style button with a one-line description under its title, not just a short label — retire earlier or later, buy or rent, Roth conversions (RRSP meltdown in the Canada version), pay off the mortgage or invest instead, Social Security/CPP+OAS timing, what happens if you live 10 years longer than planned, what's actually driving the results, what if returns are worse than expected — each pre-wired to an existing comparison rather than a blank slate. The moment the menu is expanded, each of the six comparison-style questions also grows a one-line delta preview right on the button itself (e.g. "Own → Rent: -$257.1K end assets · lasts to age 72"), so you can see the gist of the answer at a glance without clicking in — it updates live as you change assumptions while the menu is open, and always matches the full comparison a click reveals since both read the same underlying numbers. The two "jump to a chart" questions (sensitivity, historical returns) don't get a preview, since there's no two-scenario comparison to summarize. Most run the current plan against 2-4 alternatives and answer with a plain-language sentence (e.g. "Retiring 3 years earlier costs you $340K and moves your depletion age from 95 to 89") plus the numbers underneath; the last two jump straight to the sensitivity ("tornado") chart or switch the main chart to the historical S&P 500 backtest and report its success rate, switching to the Dashboard tab first on mobile if needed. The mortgage question only appears once you actually own (it has nothing to compare against if you rent). The Canada version's CPP/OAS question compares four points rather than a simple early/late toggle, since CPP's deferral credit is smaller than OAS's and a common real strategy is to take CPP around 65 while deferring OAS to 70 — a single bundled lever couldn't show that. Uses whatever numbers are currently loaded, including the generic example data before you've entered your own. Answers scroll into view automatically (switching to the Dashboard tab first on mobile if needed), and a plan that never depletes is labeled "Age N+" like the other comparison tables rather than "Never"
- **Four-tile dashboard headline, with the rest one click away**: rather than nine metrics competing for attention at once, the top of the results shows just four — investable assets at retirement, retirement age(s), the age the portfolio lasts to, and the historical success rate (from the same 1928–2025 backtest the Plan Status Bar and "Historical (S&P 500)" chart view use, computed once and shared across all three so it's never run twice) — with everything else (net worth at retirement, bond ladder funding, FI number, FIRE number, and estimated early-retirement age) tucked into a collapsed "More results" section right below. Nothing was removed or renamed under the hood — every existing metric is exactly where it was, just organized so the dashboard is easier to scan at a glance. The historical/Monte Carlo success-rate boxes tied to the main chart's "Historical (S&P 500)"/"Monte Carlo" views live with the chart itself (right below it), not inside "More results" — they only ever show while their matching chart view is selected, so burying them behind a second click to expand a collapsed section defeated the point of switching to that view in the first place
- **Collapsed "Methodology & assumptions" section**: the detailed explanation of how the model works (contribution rules, tax treatment, healthcare/ACA/IRMAA or CPP/OAS/clawback rules, and the historical-backtest methodology) is tucked into its own collapsed-by-default section below the projection table, rather than always-expanded text between the table and the footer — so it's there when you want to see exactly what's being calculated, without adding length to every page load
- **"What's driving this" shortfall banner**, and its positive counterpart: when a projection depletes before the end of the plan, a banner explains the likely cause and the smallest change that would fix it. It checks structural causes first (LTC or healthcare costs materially increasing the shortfall) before falling back to the two generic levers everyone has — spending and retirement timing — and for those two, it searches for the minimal cut or delay that actually resolves the shortfall rather than testing one arbitrary fixed amount. When the plan is healthy instead, a green "On track" banner says so directly — the age you're planning to retire, how long the money is projected to last, and roughly what's left at the end — rather than leaving the top of the dashboard silent just because there's no problem to flag
- **Couple or single-person mode**, each partner with independent ages, income, retirement date, and a configurable "plan finances through age" (life expectancy, default 100) that sets how many years the projection runs
- **Investment growth**: separate nominal return assumptions for stocks, bonds, and a high-yield savings/cash rate
- **Bond-ladder bucket strategy**: a configurable number of years of expenses held in bonds, ramped up automatically before retirement, drawn down last
- **Housing**, chosen per scenario:
  - **Own**: existing mortgage — original loan amount, remaining balance, rate, loan term (the original term, not however many years you think are left), and an optional extra-principal slider to accelerate payoff. The payment is fixed from the original loan amount and term, exactly like a real mortgage, so if you've already been paying extra, you don't need to know or guess how many years you have left — the model works that out on its own from your current balance
  - **Rent**: monthly rent with its own growth rate
  - **Rent, then buy**: rent until a chosen age, then purchase a home (cash or a new mortgage with a manually-entered loan term, down payment %, closing cost %, and extra-principal slider) — this is a fresh loan starting from the full purchase price, so there's no "years remaining" ambiguity to begin with
  - **Property tax and home insurance** are separate annual figures (each with its own growth rate, independent of general inflation), so they can be sized to the actual home rather than folded into household spending. Both apply once you own — immediately for "Own," or from the purchase year onward for "Rent, then buy" — and both keep applying after the mortgage is paid off, since they're tracked independently of the mortgage schedule
- **Pre-tax health insurance premium**: a per-paycheck amount (with a paycheck-frequency field: weekly/biweekly/semimonthly/monthly) modeling an employer-sponsored premium deducted from each paycheck while working, reducing taxable wages the same way a 401(k)/RRSP contribution does. This only applies during working years; medications, copays, and other after-tax healthcare costs are expected to be folded into household spending instead. The existing "post-retirement healthcare" field is unchanged in mechanics but now represents the insurance premium only (once retired and under 65) for the same reason
- **Toggleable long-term care costs**: an "Model long-term care costs" checkbox hides/disables the LTC fields entirely rather than requiring them to be zeroed out
- **Up to 5 additional amortizing loans** (auto, personal, etc.), each with its own original principal, remaining balance, rate, loan term, and extra payment — same fixed-payment-from-the-original-loan math as the home mortgage above, so paying extra doesn't require knowing exactly how many years are left
- **Up to 5 sequential household spending changes**, each triggered at a chosen age (e.g. mortgage payoff, empty nest, slowing down in your 80s)
- **Bridge / part-time income** per partner, with its own age window, taxed as ordinary income
- **Additional income sources**: up to 3 recurring income streams with their own start/end age, plus up to 3 one-time tax-free lump sums (e.g. an inheritance) at a specific age
- **Long-term care costs** per partner, starting at a chosen age
- **Cash reserve target**, maintained in HYSA; excess flows to brokerage
- **Withdrawal waterfall** in retirement: taxable → tax-deferred → tax-free → cash → bond reserve → home equity (last resort)
- **Cost-basis tracking** on the taxable brokerage account: a starting cost-basis %, with all new contributions added at 100% basis and withdrawals taxed pro-rata on the blended basis/gain ratio
- **Real vs. nominal dollar toggle** for every result
- **Light/dark mode toggle**: defaults to your OS/browser color-scheme preference and can be flipped from the topbar. Deliberately not persisted across reloads (unlike your plan data, below) — it just re-reads your system preference each time the page opens, so it always matches whatever your system is set to right now
- **FI#/FIRE# dashboard tiles**: FI number (25× today's household spending) and FIRE number (25× spending in your retirement year), each with a "% funded" figure measured against your current investable assets (taxable + tax-deferred + tax-free + cash, today's balances — not a future projection), plus an estimated early-retirement age (the first age, at your current savings rate, your investable assets would reach the FIRE number if you kept working and saving indefinitely rather than retiring on schedule)
- **Smoothed/proportional withdrawal toggle**: an alternative to the default "drain taxable first" withdrawal order. When enabled, each year's spending need is drawn from taxable and tax-deferred accounts in proportion to their current balances, rather than exhausting taxable completely before touching tax-deferred — this avoids the sharp jump in taxable income that happens the year taxable savings run out. It only changes the ±1yr/±3yr/CAGR views and the summary metrics; the historical backtest and Monte Carlo views keep their own bucket-strategy withdrawal order (taxable → tax-deferred → tax-free → cash → bond reserve), since that ordering is specifically designed for sequence-of-returns protection and isn't a good fit for proportional draws
- **Five chart views**: retirement date ±1 year, ±3 years, a 0–7% real CAGR sweep, a full historical backtest using actual 1928–2025 S&P 500 returns, inflation, and 10-year Treasury bond returns (Damodaran/NYU Stern dataset), and a Monte Carlo simulation. The historical backtest only replays starting years that have enough remaining data to cover the full projection length, so a longer "plan finances through age" setting (or a younger starting age) shrinks the pool of usable starting years, while a shorter one grows it. The CAGR sweep's "current" line is your actual entered assumption to the tenths place (e.g. "4.4% (current)"), not snapped to the nearest whole percent, and whichever whole-percent comparison point sits closest to it is dropped so two near-duplicate lines don't sit right next to each other
- **Monte Carlo simulation ("Monte Carlo" chart view)**: runs your choice of 500, 1,000, or 2,000 simulated futures and plots the result as a percentile fan chart (10th/25th/50th/75th/90th), alongside a success-rate metric. Instead of drawing each year's return independently at random (which can produce unrealistic strings of 100 years of straight gains or losses), each simulated path is built from randomly-ordered **5-year blocks of real historical data**, so multi-year trends, mean reversion, and the real correlation between stock returns, inflation, and bond returns are preserved within each block. Each block is drawn from anywhere across the full 1928–2025 dataset regardless of how long the projection runs, so — unlike the historical backtest below — it is not affected by the "plan finances through age" setting. Because it draws from the same 1928–2025 dataset as the historical backtest but recombines it into many more independent paths, its success rate is a different (and complementary) number from the historical backtest's — the historical view retells a small number of overlapping real 20th/21st-century sequences, while Monte Carlo dilutes any single bad era across thousands of randomly recombined paths
- **Hover-to-inspect charts**: mousing over the ±1yr/±3yr/CAGR views shows a crosshair and each series' value at that age (disabled on the historical and Monte Carlo views, which show many paths/bands at once)
- **Two-level chart controls**: rather than one row of five view buttons plus a path-count row that only sometimes applies, chart controls split into a primary "View" toggle — Projection / Historical / Monte Carlo — and a second row of options specific to whichever view is selected: ±1 yr / ±3 yrs / CAGR under Projection, or the 500 / 1,000 / 2,000-path picker under Monte Carlo. Switching back to "Projection" from Historical or Monte Carlo restores whichever of the three projection sub-views you were last on, rather than resetting to a default
- **Plain-language dollar toggle**: the header's dollar-display control reads "2026 dollars ▾" (or "Future dollars ▾"), opening a small panel with "Real dollars" (adjusted for inflation, today's buying power) and "Future dollars" (actual amounts in the year they occur) — the same underlying real-vs-nominal toggle as before, just described in plain terms instead of "Real $ / Nominal $"
- **Quieter top banner**: the top-of-page notice now reads a compact "Planning estimate · Learn about limitations" instead of a full paragraph-length warning. Clicking "Learn about limitations" opens (and scrolls to) a "Limitations & disclaimer" callout at the top of the "Methodology & assumptions" section, which carries the full disclosure — the warning is still one click away, it just doesn't dominate the first thing you see
- **Collapsible sensitivity analysis ("tornado chart")**: shows how far projected end assets swing when one assumption moves at a time, holding everything else fixed, sorted by impact. Five assumptions (investment return, retirement age, household spending, inflation, bond return) are checked by default; five more (HYSA/cash rate, home appreciation, healthcare premium, long-term care cost, Social Security/CPP+OAS) are available via checkbox but off by default. Each swing is a fixed ± amount, e.g. "±2pp" (percentage points) or "±10%", not a probability distribution — a dashed line, labeled with its value, marks the current projection's end assets for comparison. If the current plan is projected to run out of money before the end of the modeled horizon, end assets would show $0 for every single bar (masking real differences between assumptions), so the chart automatically switches to measuring peak portfolio value instead — the dashed line is then labeled "Current (peak)" and a note under the chart explains the switch. Collapsed by default and only computed while expanded, so it never slows down the main dashboard
- **Scenario overlay chart**: once any saved scenario is checked for comparison, a chart appears plotting each checked scenario's total-assets-by-age alongside "Current," so you can see the shape of the difference, not just the summary numbers in the comparison table
- **Guyton-Klinger guardrails (opt-in toggle, off by default)**: a simplified dynamic-spending strategy. Instead of a fixed inflation-adjusted spending amount, household discretionary spending is cut 10% when your withdrawal rate runs materially above your rate at retirement (capital-preservation rule) and raised 10% when it runs materially below it (prosperity rule), so you can toggle it on to see how a dynamic policy changes the outcome versus a fixed one
- **Survivor planning (opt-in toggle, off by default)**: models one partner dying at a chosen age. From that year onward: the household switches to single filing, the survivor keeps the greater of the two Social Security (or CPP + OAS) benefits — a simplified survivor-benefit swap rather than full PIA/FRA or CPP survivor-pension rules — the deceased partner's pension/LTC/healthcare share drops out, the tax-deferred account balance consolidates under the survivor's own RMD/RRIF-minimum schedule, household spending is cut to a configurable percentage, and any "other loans" balance is paid off as a lump sum in the year of death (approximating debts settled through the estate/probate before assets pass to the survivor). The mortgage is untouched, since it's secured by jointly-titled real estate. On the Canada planner, pension income splitting also disables itself for the survivor period, since it requires two living spouses. Intended for a death during retirement; one modeled during a working year may not fully zero out that year's payroll activity
- **Cash-flow Sankey diagram** (collapsible, only computed while expanded): for a single selected year (a slider steps through the whole projection), shows where that year's money comes from (wages, Social Security/CPP+OAS, pension, traditional/RRIF withdrawal, taxable/brokerage withdrawal) on the left and where it goes (taxes, housing, healthcare, LTC, loan payments, discretionary spending) on the right, funneled through a single "pooled cash flow" hub in the middle — any remaining gap (Roth, cash, or home-equity draws; or a surplus) is shown as "From portfolio"/"To savings". The traditional and taxable/brokerage source amounts include whatever was drawn from the matching slice of the protected bond reserve (bondTraditional/bondTaxable), not just the equity sub-account, so a year that's still drawing bond-reserve money doesn't understate them. Hover (or focus via keyboard) any income source, hub, or spending category for its exact dollar amount
- **Log-scale chart toggle**
- **CSV export** of the full year-by-year projection
- **Print/PDF report**: a formatted, landscape-oriented summary (assumptions, results, and a year-by-year income/expenses/tax table) generated from the current inputs, ready to print or save as a PDF
- **Named scenarios**: save the current inputs as a named snapshot, load any saved scenario back, and check any number of them for a side-by-side **scenario comparison table** (retirement age, investable/net worth at retirement, how long the portfolio lasts, end assets — each vs.-Current column shows a green/red delta) and **overlay chart** (above) alongside your live "Current" inputs, which updates as you type. Scenarios live in the browser tab only until exported — export any scenario (or all of them at once) to a JSON file to keep past the session or carry into a future update, and re-import it later. Every load path (boot, Load, and import) merges the saved data over the current defaults, so a scenario exported by an older or newer version of the tool still loads correctly: missing fields fall back to today's defaults, and fields that no longer exist are simply dropped — nothing breaks
- **Confirmation before Reset, plus a 10-second Undo**: since Reset clears what's saved in this browser, clicking it asks first, and either Reset or loading a saved scenario also pops up an "Undo" toast for a few seconds afterward in case you change your mind (importing a scenario file doesn't need this — it only adds to your saved list without touching what's currently loaded)
- **Comma-formatted dollar fields**: every balance, income, or expense field displays its value formatted with a "$" and thousands separators ("$1,850,000") right in the field as you type, rather than as a plain unformatted number
- **Sidebar field search**: a search box above the assumptions panel filters the whole sidebar down to just the fields whose label matches, opening (and, once nothing in them matches, re-closing) whichever collapsible groups actually contain a match as you refine the search — restored to however everything was once you clear it. It also shows a dropdown of up to 8 matching fields with a group breadcrumb (e.g. "Mortgage interest rate / Housing"); click one, or arrow to it and hit Enter, to jump straight to it — opening its group, scrolling it into view, and focusing it — without having to scan the filtered sidebar yourself
- **A dot marks any field still at its generic-example value**, refreshed live as you type — so a scenario you've only partially personalized still shows what's actually yours vs. what's still the placeholder. Separate from (and longer-lasting than) the one-time first-run banner
- **"Estimated" badges + a dashboard rollup for the personal facts that still need your numbers**: on top of the quiet dot above (which covers every default-valued field, including generic modeling assumptions like return rate or inflation that are fine left alone for most people), fields that are specifically about *you* — ages, income, account balances, spending, mortgage terms, Social Security/CPP+OAS, and similar, including the fields inside an opt-in feature once you've turned it on — get an explicit amber "Estimated" badge (a plain "Estimated" label next to its own small ✓ circle — the only tappable part) while still at default. A dashboard banner ("N of your numbers are still estimated · Review →") tracks how many remain; clicking "Review →" jumps straight to the first one, opening its section, scrolling to it, and highlighting it. From there, "Next →" — reachable from a small floating pill that follows you onto the input screen, so you're never stuck switching tabs by hand to keep going — confirms the current field looks right and advances to the next one, so reviewing reads as one continuous flow rather than a list to hunt through. If a number is fine left at its default without stepping through the guided flow, the badge's own ✓ dismisses it directly. Either way the dismissal is persisted — across reloads, and through saving/loading or importing a scenario — and editing that field later automatically un-dismisses it. The rollup disappears once nothing's left to review
- **"Worth a second look" — a warning for unrealistic modeling assumptions**: separate from the badges above (which are about *your* numbers, like income or account balances), this flags *modeling* assumptions — investment return, inflation, bond return, HYSA rate, income/home/rent/property-tax/insurance growth, bond pool size, mortgage rate, life expectancy — whenever the current value sits outside a realistic real-world range (a 15% return, a 0% inflation rate, and so on all pass the field's own input limits but aren't a sane planning assumption). A dashboard banner lists what's flagged, along with what switching to a typical value would do to your plan's end assets and how long it lasts, and a small pop-up briefly appears even if you're looking somewhere else on the dashboard (or on the Inputs tab on your phone) whenever something *newly* becomes unusual — but not again if you nudge that same field to a different unusual value. Each item has its own ✓ to say "I meant this" and stop flagging it, which is remembered across reloads and only resets automatically once you actually bring the value back into a normal range and later push it out again. There's also a quieter cue right where you're typing: a flagged field gets a red-bordered/underlined outline the moment its value goes out of range, and a brief "Unusual value" note appears once you move on to the next field — so you don't have to be looking at the dashboard to notice, and even the very last field you edit gets flagged without needing you to click away first. Ages and retirement age are deliberately left out of this — this is a FIRE app, retiring in your 30s or 40s is the point, not something to be warned about
- **Every collapsed sidebar section shows a one-line summary of what's already set**, so you don't have to open a section to know what's in it — e.g. "Retire 55 · plan to 100" or "Own · $830K · $619K mortgage". Optional features (other loans, part-time income, additional income, survivor planning, Roth conversion/RRSP meltdown/Guyton-Klinger/pension-splitting strategies) show a green checkmark and a summary once turned on, and show nothing at all — not even "Off" — until then, so a first-time visit looks exactly as simple as before this existed
- **Independently-scrolling sidebar**, so the assumptions panel and the results (chart/table/notes) scroll separately, sized to fit the visible window so its bottom is never below the fold
- **Plan status bar**: a compact summary — retirement age(s), portfolio value at retirement, whether the plan runs out and when, and a historical success rate — pinned to the top of the screen as you scroll on both desktop and mobile, so you're never far from the model's current answer even deep into the charts and tables below. Click it to jump straight to the main results tiles. On a phone-width screen it wraps onto a couple of lines instead of cutting the summary off mid-sentence. On mobile, a small "minimize" button lets you collapse the sticky Inputs/Dashboard tabs and search box (which stack directly below the status bar) to reclaim screen space — handy once the on-screen keyboard is open; the status bar itself always stays visible and is left out of that toggle. "Your assumptions" doesn't get its own header on mobile — the Inputs tab already makes that clear, so it's just search + fields.
- **Mobile-responsive layout**: usable on a phone-width screen. Below 820px wide, an "Inputs / Dashboard" tab bar replaces the stacked one-long-scroll layout — Inputs shows the assumptions panel, Dashboard shows the results (verdict/metrics/chart/table/notes/question menu) and is what you land on by default (and again after finishing the setup wizard), since the results are the actual point of the tool; switching between them re-renders the dashboard so its charts always measure their container at the correct, visible width. A "Change assumptions →" button under the plan verdict jumps straight to the Inputs tab (and scrolls to the top) as a more obvious path than relying on the tab bar alone; it only appears on mobile. Chart-view buttons also wrap instead of overflowing. Desktop is unaffected — the two-column layout there ignores the tabs entirely
- **Accessibility**: every control has a real label or `aria-label`, charts have descriptive text alternatives, text meets WCAG AA contrast in both light and dark mode, and scrollable result tables are reachable by keyboard
- **In-page MCP tool hooks** (`read_fire_projection`, `update_fire_assumptions`) for programmatic/agentic access to the live projection
- **Nothing is transmitted, and nothing leaves your device** — your inputs autosave to this browser's own `localStorage` so a reload or a later visit picks up where you left off, but that's the extent of it: no server, no account, no analytics, and nothing sent over the network. Clearing your browser's site data, using a private/incognito window, or clicking "Reset" all wipe it the same way local-only storage always has. The very first visit (or a visit where nothing's been edited yet) never writes anything — there's nothing personal to save until you actually enter something, open the wizard, or import a scenario

## US-specific (`Planner_US.html`)

- Federal tax brackets + all 50 states' income tax rules
- 401(k) and IRA accounts, each selectable as Traditional or Roth, with employer match modeling
- Catch-up contributions (age 50+, enhanced age 60–63), auto-Roth above the SECURE 2.0 wage threshold
- Mega backdoor Roth
- Social Security, with a start-age slider per partner
- Medicare IRMAA surcharge modeling
- ACA premium tax credit (2026 sliding-scale structure, with an option to model the enhanced ARPA/IRA-style subsidy instead)
- **Post-retirement healthcare only applies once both partners have stopped working.** A retired partner is assumed to be covered under a still-working spouse's employer plan (size that partner's own per-paycheck premium field to include a non-working spouse, if that's the real cost) rather than needing their own individual ACA/COBRA policy — so for a couple, the "annual post-retirement health insurance premium" input doesn't start for either partner until neither is working, even if one retires years before the other
- Required Minimum Distributions (RMDs)
- 10% early-withdrawal penalty: any discretionary traditional/bond-traditional withdrawal taken before age 59½ is penalized unless the withdrawing partner is covered by Rule of 55 or a 72(t) SEPP plan; traditional is a single pooled household balance rather than split per partner, so a withdrawal is treated as half-penalized when only one partner is currently exempt
- **Rule of 55** (opt-in toggle, off by default): waives the 10% penalty on traditional withdrawals from age 55 through 59½, for whichever partner retires at or after 55 — doesn't apply to a partner retiring before 55
- **72(t) SEPP payments** (opt-in toggle, off by default): for a partner retiring before 59½, models a mandatory, penalty-free annual distribution using the IRS "RMD method" (balance ÷ IRS Single Life Expectancy Table divisor, recalculated each year) from their retirement age through the later of 5 years or age 59½ — taxed as ordinary income exactly like an RMD. Only the SEPP-scheduled amount is protected; any further discretionary withdrawal that same year is still subject to the 10% penalty unless otherwise exempt, matching how a real SEPP plan only protects its own fixed schedule
- Roth conversion ladder: solves for the annual conversion that fills a chosen federal tax bracket, automatically capped so it never pushes MAGI over the ACA subsidy cliff (400% FPL, when ACA premium tax credits are enabled and not using the enhanced-subsidy option) or into the next Medicare IRMAA tier (once within 2 years of 65, using the 2-year MAGI lookback) — the bracket target becomes a ceiling on the conversion, not a guarantee that the full bracket gets filled. This is US-only, since Canada has no equivalent income-tested healthcare cliff to model (see the RRSP meltdown ladder below for Canada's closest analog)
- **Bracket optimizer** (collapsible, only shown and computed while the ladder is enabled/expanded): re-runs the plan at every available bracket-fill target and reports which one minimizes estimated lifetime tax (income + payroll, summed across the projection in today's dollars), guarding against a recommendation that would shorten how long the portfolio lasts
- MFJ vs. single filing status, with an optional "marry later" age

## Canada-specific (`Planner_Canada.html`)

- Federal tax brackets + provincial tax for all 10 provinces (Ontario, BC, Alberta, Saskatchewan, Manitoba, Quebec, New Brunswick, Nova Scotia, PEI, Newfoundland and Labrador), including Ontario's Health Premium and two-tier surtax, and Quebec's 16.5% federal tax abatement. Territories are not modeled
- RRSP and TFSA accounts, with CRA contribution-room rules
- FHSA (First Home Savings Account): $8,000/year and $40,000 lifetime cap per partner, usable toward a future home purchase (see "Rent, then buy" above), with automatic tax-free rollover of any leftover balance into the TFSA
- CPP (start age 60–70) and OAS (start age 65–70), with OAS recovery tax (clawback) modeled
- RRIF minimum withdrawal rules starting at age 71
- RRSP meltdown ladder: solves for the annual RRSP withdrawal that fills a chosen federal tax bracket, moving proceeds to TFSA
- **Bracket optimizer** (collapsible, only shown and computed while the ladder is enabled/expanded): re-runs the plan at every available bracket-fill target and reports which one minimizes estimated lifetime tax (income + payroll, summed across the projection in today's dollars), guarding against a recommendation that would shorten how long the portfolio lasts
- Pension income splitting between partners (up to 50% of eligible pension/RRIF income), solved to minimize combined household tax
- No RRSP/RRIF early-withdrawal penalty is modeled, because Canada has none to model: RRSP funds can be withdrawn at any age with no age-based penalty, only withholding tax (a prepayment against the tax already computed via `taxFor()`, not an extra cost) and permanently losing that contribution room — unlike the US's 401(k)/IRA 10% early-withdrawal penalty (see US-specific above)

## Versioning

These files use **stable filenames** — always `Planner_US.html` / `Planner_Canada.html`, never version-numbered suffixes. Version/date info can live in the on-page header if useful, but the filename itself never changes. This means:

- `index.html`'s links never go stale.
- Every update is just a `git commit`, not a rename-and-fix-links exercise.
- Full history (what changed, when, why) lives in `git log` instead of a pile of old files.

## Testing

`npm test` runs `tests/golden.js`, which checks the core drawdown and compounding math against hand-verified year-by-year figures to the cent. A GitHub Actions workflow (`.github/workflows/test.yml`) runs this on every push. There is no automated coverage of the UI itself beyond this; changes to interactive behavior are currently verified ad hoc (e.g. with Playwright) rather than via a committed test file.

## Making an update

1. Edit the file (or have Claude edit it).
2. Save it back over the same filename (`Planner_US.html` / `Planner_Canada.html`) — don't create a new versioned copy.
3. If the change adds or changes a user-facing feature, update this README's feature list in the same batch of work. If it changes anything architectural (a new shared helper, a new gotcha, a new divergence between the US and Canada files), update `CLAUDE.md` too.
4. Commit the change with a short message describing what changed.

Keeping README.md and CLAUDE.md current alongside the code (rather than as an occasional separate pass) is what lets a future session — one with no memory of this conversation, possibly running in a different, disconnected copy of this repo — pick up accurately from just the repo contents.

If you're using GitHub Desktop: open the app, you'll see the changed file listed, write a one-line summary in the box at bottom left, click **Commit to main**, then click **Push origin** to sync it to GitHub.
