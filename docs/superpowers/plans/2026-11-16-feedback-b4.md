# Feedback B4: say when history sets the verdict word (plan, 2026-11-16)

Item B4 of `docs/superpowers/specs/2026-11-15-first-user-feedback-plan.md`, the first user's note #1: the planner must never
look rosier than it should. Today a plan that lasts with plenty of room in the average market but runs out in many historical
start years reads "Tight" beside a sentence that only says how much more it could spend; nothing says why it is Tight. Both
planners (the verdict is shared). One PR against `main` (at 6becc7a, PR #104 merged). Badges: US V183 → V184, Canada V87 → V88.

## The owner's decision (2026-11-16)

The verdict keeps leading with the average-market sentence (how long the money lasts, and the spending room or the cut). The
Comfortable / Tight / Short word stays judged on both measures, as today (`VERDICT_RULES`: Tight under 10% room, more than a 10%
guardrail cut, or under 80% historical success). What changes: when the historical success rate is what sets the word (the
average-market margin alone would have said Comfortable), the sentence says so in plain words. Recorded in the spec's B4 entry in
this PR.

## The design

### Which measure set the word (core)

In `src/shared/core/analysis/spending-room.js`, split `marginOk` out and add one export beside `planVerdict`:

```js
  // Whether the margin alone (spending room, or with guardrails the deepest cut) reads Comfortable.
  function marginOk({ roomShare, guardrails, cutPct }) {
    return guardrails ? cutPct <= VERDICT_RULES.maxGuardrailCutPct : roomShare >= VERDICT_RULES.minRoomShare;
  }

  export function planVerdict(args) { ... unchanged result, using marginOk(args) ... }

  // Whether the historical success rate alone set the word: the plan lasts, its margin reads Comfortable, and the backtest (not
  // ignored for a scenario, and landed) is under the line. Only then does the verdict say that history made it Tight.
  export function historySetsWord({ depleted, roomShare, histRate, guardrails, cutPct, scenario }) {
    return !depleted && !scenario && histRate != null && histRate < VERDICT_RULES.minHistSuccess &&
      marginOk({ roomShare, guardrails, cutPct });
  }
```

`planVerdict`'s results do not change (its Vitest table stays as is).

### The words (core, new module)

`src/shared/core/format/history-text.js` (line 1: `// The historical backtest in words: a success percent that never reads 100% after a failure, and the share that ran out`):

```js
  // The success rate as a whole percent, rounded down so a rate under a line never reads as the line (0.796 → 79) and a rate
  // under 1 never reads 100 (0.995 → 99). The 1e-9 keeps a float product like 0.29 * 100 (28.999999999999996) at 29.
  export function successPercent(rate) {
    return rate === 1 ? 100 : Math.min(99, Math.floor(rate * 100 + 1e-9));
  }

  // The starting years that ran out, as the phrase after "runs out in": the exact count, never rounded (failed > 0).
  export function failedYearsText(failed, total) {
    return failed === total
      ? `every one of the ${total} historical starting years since 1928`
      : `${failed} of the ${total} historical starting years since 1928`;
  }
```

`failed` comes from the cycles (`cycles.filter((c) => c.depletedAge).length`), not from the rate, so it is exact. "Starting
years" matches the Historical chart view's own wording.

**Revision after the plan review (1):** the first draft rounded to "about 1 in N" with N = round(total / failed). The review
showed that this can read on the passing side of the line: 15 of 70 (78%, Tight) reads "about 1 in 5", that is 80% held up.
Rounding toward more failures instead (N = floor) overstates: 18 of 70 (26%) would read "about 1 in 3". The exact count needs no
rounding rule at all, so it is the recommendation put to the owner; the alternative offered is "about 1 in N" rounded toward
more failures, with the count in brackets. **Owner's answer:** (recorded here before implementation).

### The card (ui)

`plan-verdict.js`:

- The backtest stores `verdictHistFailed` and `verdictHistTotal` beside `verdictHistRate` (module-level `let`s, assigned only
  there, all three in the same statement block). A null `successRate` (a horizon longer than the 1928-2025 record) sets all
  three to null, as today's rate already is, so a stale rate never holds the word.
- `lastVerdict` gains `byHistory` (`historySetsWord(...)` with the same arguments as `planVerdict`), set on render and re-decided
  when the backtest lands, exactly where `word` is.
- `paintPlanVerdict` appends one sentence, in a `<span class="verdict-hist-reason">`, to the existing sentence when
  `v.byHistory`; nothing else in the sentence changes. The span takes `.stale` together with `#planVerdictHist` (added in
  `scheduleVerdictHistRate`, removed when the backtest lands), so a plan just edited does not show the previous count at full
  contrast (review finding 6). The CSS dims it as `.verdict-hist.stale` is dimmed.
- `statusBarText` says `Tight (history)` for the word when `v.byHistory`.
- The historical line, the status bar's clause and the `#dashHistSuccess` tile use `successPercent` (the tile's colour stays on
  the raw rate). The same helper replaces `toFixed(0)` in the two chart views' historical and Monte Carlo rates
  (`ui/charts/chart-view.js`, both countries) and the US plan card's `rateText` (`src/us/ui/results/plan-optimizer.js:31`), so no
  display of a success rate reads 100% after a failure or reads the 80% line when it is under it. Colours and thresholds are
  unchanged.
- **A bug found on the way (its own commit, before the feature):** with a null rate the `#dashHistSuccess` tile shows "0%" in the
  negative colour (`plan-verdict.js:169`, `(null * 100).toFixed(0)`). It shows "—" with no class, as the Historical chart view
  does. Stated in that commit.
- A test hook `window.__test_flushVerdictHist()` (in `src/shared/ui/install-test-hooks.js`) runs a pending backtest now
  (`flushVerdictHistRate()` exported from `plan-verdict.js`: clear the timer, run its body). A Playwright test calls
  `__test_flushRender()` then `__test_flushVerdictHist()` before reading the word, the sentence or the bar, instead of waiting
  for the line's text, which keeps the previous rate while the next is pending (review finding 2).

### The exact sentence variants

`R` is the retiring text ("Retiring at 55" or "Retiring at A 55 / B 57"), `E` the end age, `N`/`T` the failed and total start
years. Bold is `<b>` as today; `ROOM` is the hover target `.verdict-room` as today.

| Case | Word | Sentence (`#planVerdictText`) | Status bar |

| **Room ≥ 10%, history < 80%** (new) | Tight | R, your money lasts through age E in an average market. You could spend about **ROOM $12,000 more a year** (today's dollars) and still make it. **But it runs out in 22 of the 70 historical starting years since 1928.** | `Tight (history) · +$12K/yr room · 68% historical` |

The historical line under the sentence is unchanged in wording (`Held up in 74% of historical markets since 1928 · see the bad
ones`), now with the rounded-down percent. With everything else the same, a plan the history alone makes Tight reads:

> **Tight**
> Retiring at 55, your money lasts through age 95 in an average market. You could spend about **$12,000 more a year** (today's
> dollars) and still make it. **But it runs out in 22 of the 70 historical starting years since 1928.**
> Held up in 68% of historical markets since 1928 · see the bad ones

(Illustrative counts. A real case: the default household with a 10% return and $66,000 spending reads, on `main` today, "Tight ·
+$12K/yr room · 68% historical" in the US planner, with nothing saying why it is Tight.)

Why these choices:

- "in an average market" is added only in the new case: elsewhere the sentence does not need to contrast two measures, and
  adding it everywhere would move every snapshot for no gain. The review noted the projection is really "your fixed return"
  (the moves say "in the projection"); "an average market" is the owner's own phrase for it, so it stays unless the owner picks
  otherwise when shown the variants.
- The exact count can never read as zero failures (it is at least 1; "every one of the T" covers all of them) and needs no
  rounding rule.
- "Tight (history)" keeps the bar short on a phone (it wraps there already) and says which measure set the word.
- Both measures failing (small room and weak history) keeps today's sentence: the room figure already explains Tight, and the
  historical line beneath shows the rate. Short on both measures likewise: the run-out sentence is the reason.

### The moves list (PR #99)

No change in this PR: a history-only Tight still gets no moves card, since no move is tested against history and the moves
would each read "Comfortable in the projection". **Asked of the owner** (with the sentence variants): keep that, or show the
moves card with a single line in its place, for example "These changes are tested in the average market only, which this plan
already passes. Try a market scenario or the Historical view to test them against bad years." Whatever the owner picks is
recorded here before implementation.
