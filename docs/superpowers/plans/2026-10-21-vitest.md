# Vitest unit tests for core/ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the pure-function `core/` tests of both planners under Vitest, straight from `src/` (no build, no browser), converting four pilot suites and then a bounded first wave, with every assertion kept exact.

**Architecture:** One `vitest.config.mjs` with two projects (`us`, `canada`) that make `#country/*` resolve for their country. Tests live in `tests/unit/`; a `world()` helper gives every test a fresh module graph (mechanism R) or, if the spike rules R out, a hand-kept reset list plus a behavioral guard (mechanism L). Nothing under `src/` changes.

**Tech Stack:** Vitest (pinned exact), Node ESM, the existing CommonJS test helpers loaded with `createRequire`.

**Spec:** `docs/superpowers/specs/2026-10-21-vitest-design.md` (approved by the owner 2026-10-21). Read it first; section numbers below refer to it.

## Global Constraints

- No change to anything under `src/`, to `tests/snapshots/`, or to any number a planner produces (spec section 2). A bug found by a conversion is reported, not fixed.
- Exactness: numbers with `expect(a).toBe(b)` (`Object.is`), objects with `toStrictEqual`, never `toBeCloseTo`; an old `===`, `==` or `Math.abs(...) <= tol` comparison is written out unchanged, no looser and no stricter; hand-computed expected values stay literals (spec section 6).
- `vitest` is a pinned `devDependency` (exact version, no `^`), the newest release at least two weeks old when Task 1 runs; Vitest 5 needs Node 22.12 or newer; CI uses Node 22, local Node is 24.
- The config is `vitest.config.mjs`; test files are `tests/unit/**/*.test.js`; `it.concurrent` is never used.
- `TEST_YEAR` is 2026; the system time is pinned by `tests/unit/clock.js`, the first `setupFiles` entry, which imports nothing from `src/`.
- `package.json` and the lockfile change in Task 2 and nowhere earlier (the spike is throwaway and committed nowhere).
- A conversion is one commit and deletes the old script, its `npm test` chain entry and its CLAUDE.md mention in that same commit.
- `npm test` ends with `snapshot.js` and `snapshot_ui.js`, unchanged; "not slower" is judged on the whole of `npm test` at the end of the first wave (Task 7), target at most about 60 s added.
- Repo rules: edit `src/` never `dist/`; no `git stash`; commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; do not push or open a PR unless the owner asks; Windows host, use the Bash tool for the commands below.
- Work on a new branch `claude/vitest-impl` cut from `claude/vitest-design` (this plan and the spec travel with it).

## Review Focus

Failure modes the spec implies that no conversion's own assertions exercise; each gets a test in the task named.

1. A converted suite passes alone but fails when the files run shuffled or in another order (Task 2 acceptance run; Task 3 to 6 each run alone and shuffled).
2. A synthetic rule row (`zz…`) reused across `it` blocks silently evaluates a previous test's cached rule (Task 4: a test that registers the same code twice through `withRuleRow` and expects the second registration to be seen).
3. A tolerance-0 `near(x, 0)` accepts `-0` in the old script; a mechanical `toBe(0)` would reject it (Task 5: the ported helper keeps `Math.abs`, and a test pins that `-0` passes it).
4. The wall clock crosses a year boundary or the host runs in another timezone, shifting a hand-computed 2026 figure (Task 2: `clock.test.js` asserts `CURRENT_YEAR === 2026` in both projects).
5. Node 22 and Node 24 disagree in the last bit of a `Math.pow` result (Task 1 and Task 7 compare every pilot figure, not pass/fail).
