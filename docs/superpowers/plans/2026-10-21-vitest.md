# Vitest unit tests for core/ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the pure-function `core/` tests of both planners under Vitest, straight from `src/` (no build, no browser), converting four pilot suites and then a bounded first wave, with every assertion kept exact.

**Architecture:** One `vitest.config.mjs` with two projects (`us`, `canada`) that make `#country/*` resolve for their country. Tests live in `tests/unit/`; a `world()` helper gives every test a fresh module graph (mechanism R) and tests reach `src/` only through it. If the spike rules R out, a separate Task 2L is written first (a hand-kept reset list plus a behavioral guard, spec 5.3).

**Tech Stack:** Vitest (pinned exact), Node ESM, the existing CommonJS test helpers loaded with `createRequire`.

**Spec:** `docs/superpowers/specs/2026-10-21-vitest-design.md` (approved by the owner 2026-10-21). Read it first; section numbers below refer to it.

## Global Constraints

- No change to anything under `src/`, to `tests/snapshots/`, or to any number a planner produces (spec section 2). A bug found by a conversion is reported, not fixed.
- Exactness: numbers with `expect(a).toBe(b)` (`Object.is`), objects with `toStrictEqual`, never `toBeCloseTo`; an old `===`, `==` or `Math.abs(...) <= tol` comparison is written out unchanged, no looser and no stricter; hand-computed expected values stay literals (spec section 6).
- `vitest` is a pinned `devDependency` (exact version, no `^`), the newest release at least two weeks old when Task 1 runs (if only a 4.x qualifies, record it and continue; the spec's Node 22.12 note and `test.provide` syntax then need a check); Vitest 5 needs Node 22.12 or newer; CI uses Node 22, local Node is 24.
- The config is `vitest.config.mjs` with `testTimeout: 60000` (the old sweeps run for seconds); test files are `tests/unit/**/*.test.js`; `it.concurrent` is never used.
- `TEST_YEAR` is 2026; the system time is pinned by `tests/unit/clock.js`, the first `setupFiles` entry, which imports nothing from `src/`.
- `package.json` and the lockfile change in Task 2 and nowhere earlier (the spike runs in its own scratch worktree and is discarded).
- A conversion is one commit and deletes the old script, its `npm test` chain token and every CLAUDE.md mention in that same commit.
- `npm test` ends with `snapshot.js` and `snapshot_ui.js`, unchanged; "not slower" is judged at the end of the first wave (Task 7), target at most about 60 s added.
- Repo rules: edit `src/` never `dist/`; no `git stash`; commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; do not push or open a PR unless the owner asks; Windows host with Git Bash, use the Bash tool for the commands below; do not touch the other worktrees (`fp-core-regroup`, `fp-stage4-impl`, `fp-main-check`, `C:\Users\Alex\code\Fire-Planner`).
- Task 1 runs in a scratch worktree and commits only the spec's section 10 to `claude/vitest-design`; Tasks 2 onward happen on a new branch `claude/vitest-impl` cut from it (Task 1 Step 8).
- Vitest 5.0.3 (published 2026-09-30) is expected to be the only release at least 14 days old on 2026-10-21; Task 1 confirms. Its engines are `^22.12 || ^24 || >=26`.

## Conversion rules (Tasks 3 to 6 and 8)

- **Unit of parity.** The old script's *executed named checks*: every call of its own `ok` / `near` helper and every `assert.*` call, excluding page-error checks (`ok('no page errors')`, `assert.deepStrictEqual(errors, [])`, which have no unit-test equivalent and are named in the commit message). Count them once in a **scratch copy** of the old script (not committed): add a counter to its helpers (for helpers that run inside `page.evaluate`, increment a `window` counter and read it at the end) and preload `node -r <scratch>/count-assert.js` that wraps `require('assert')`'s methods to increment a counter; print the total. That is `OLD_COUNT`.
  The new file counts through `tests/unit/helpers/count.js` (Task 2): `const c = makeCounter()`; ported `ok` / `near` helpers call `c.tick()`, and a direct comparison is written `c.expect(x).toBe(y)` (which ticks then returns `expect(x)`). An `afterAll(({}, suite) => { if (suite.tasks.some((t) => t.mode === 'skip')) return; expect(c.total).toBe(NEW_COUNT); })` asserts the total (so a filtered `-t` run, `.only` or a skip does not fail it; `process.argv` inside Vitest's workers does not carry CLI flags, so it cannot be used). The first argument of `afterAll` must be a destructuring pattern (`({}, suite)`); `(suite) =>` and `(_ctx, suite) =>` throw `FixtureParseError`. `NEW_COUNT` equals `OLD_COUNT` (page-error checks excluded); never assert a count from the last `it` (shuffle).
- **State.** `setState(patch)` normalizes; the old scripts often apply raw patches in place. To keep the same inputs, call `const state = await w.setState()` and then `Object.assign(state, patch)` on the returned object. Always read `state` from `store.state` on the module namespace or use the object `setState` returned; never destructure `state` from a namespace before a later `setState` (it is a live binding that `assignState` replaces). Hold no module-level cache of a `src/` module in helpers or tests.
- **Mutation check** (suites with more than a handful of checks): `git diff --quiet -- src` must hold first; make the named mutation; `npm run build`; confirm the old script and the new file both fail; `git checkout -- src`; `npm run build`; `git diff --quiet -- src tests/snapshots` must hold again.
- **Before each conversion commit:** `git diff --stat -- src tests/snapshots` is empty; `git diff package.json` shows only the one script token removed from `test`; `grep -rn "<deleted script name>" CLAUDE.md README.md docs tests` and update every hit in CLAUDE.md, README.md, undated docs (`docs/reference.md`, `docs/roadmap.md`) and comments in `tests/*.js` (such as `tests/benefit_rules.js`, `tests/gis_tables.js`, `tests/state_reference.js`); leave dated plans and specs (`docs/superpowers/plans/2026-*`, `docs/superpowers/specs/2026-*`, `docs/next-batches-plan.md`) as historical records, and leave comments under `src/` alone (no `src/` edits) noting them in the commit message (CLAUDE.md names these scripts in about a dozen places; `tests/doc_paths.js` only checks `src/` paths); stage explicitly: `git add <new test> package.json CLAUDE.md <other edited docs>`, `git rm <old script>`, then `git status --short`; run alone, then the whole `npx vitest run --sequence.shuffle`, then `npm test`.
- **Stand-ins for hooks.** Known aliases: Canada's `__test_tax.incomeTax` is `incomeTaxCA`; its `payrollItems` is a wrapper returning a copy (`(w, y) => ({ ...payrollItems(w, y) })`, so copy before the next call); `__test_simulateRaw` / `__test_simulateHistoricalRaw` exist only in the US installer. Check every `window.__test_*` hook the old script uses against `src/<country>/ui/install-test-hooks.js`: a hook that re-exports a `core/` function is imported from its `core/` module; a hook defined inline there (for example `__test_rowFnFor`, `__test_runPlanMode`, `__test_setRothOverride`, `__test_planTrace`, `__test_solver`) has no importable equivalent: port its logic into a helper under `tests/unit/helpers/` if it is small, else leave those checks in Playwright and say so in the commit.

## Review Focus

Failure modes the spec implies that no conversion's own assertions exercise; each has a test in the task named.

1. A synthetic rule code registered twice in one world reads the first row's cached compiled rule (Task 2: `withRuleRow` throws on a second registration of the same code in a world; the test expects the throw).
2. A helper or test imports a `src/` module itself (static `import`, `import()`, `vi.importActual`, `require` of a `src/` path) while `world().load` returns another instance, so stores and caches split silently; or a stale world's `load()` resolves into a newer world's graph (Task 2: a scan forbids these outside `world.js`, a test proves two `load()` calls in one world return the same instance and a second `world()` a different one, and `load()` on a superseded world throws).
3. A converted tolerance-0 `near(x, 0)` is turned into `toBe(0)` and rejects `-0` (Task 5: the ported helper keeps the old 4-argument `near(a, b, tol, label)` and a test pins that it accepts `-0`; the rule that a tolerance-0 check stays a `near` is in the Conversion rules and checked by the executor's review of the diff).
4. The host clock or timezone shifts a hand-computed 2026 figure (Task 2: `clock.test.js` asserts `CURRENT_YEAR === 2026`; `clock.js` uses the local-time constructor, so the year is 2026 in every timezone, and Tasks 2 and 7 run the suite once from PowerShell under `$env:TZ = 'Pacific/Kiritimati'` and `'Pacific/Pago_Pago'` as a smoke test for any other use of `Date`; Git Bash's `TZ=... cmd` prefix does not reach native processes and must not be used).
5. Node 22 and Node 24 disagree in the last bit (Task 1 and Task 7 compare printed hashes of engine rows, `taxIndexFactor` values and `stateIncomeTax` results, not pass/fail).
6. A check count asserted from the last test in a shuffled file (the count lives in `afterAll`, Conversion rules).
