# E2: adoption, a child who joins the household after birth (US and Canada) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let each child row carry an optional "Joins the household in" year, so an adopted child counts as a dependent
from the year it joins (for the whole join year) instead of from its birth year, in both planners, with a blank field
meaning from birth and every legacy save and snapshot unchanged.

**Architecture:** One condition in the shared `dependentsInYear` (and the same one in the US-only `hasChildAtMost`, the
one reader that loops over `state.children` itself) skips a child whose join year is later than the tax year; every
other reader already goes through `dependentsInYear`. The shared `normalizeLists` keeps `joinYear` only when it is a
year later than the birth year, so a legacy row keeps its exact shape. The shared list renderer gains an opt-in blankable
number field (`blank: true`, `placeholder`), which each planner's own `DYN.children` spec uses for the new field.

**Tech Stack:** `Planner_US.html`, `Planner_Canada.html` (one inline `<script>` IIFE each, no build), the shared fragments
`shared/01-LIST_MAX.js` and `shared/23-dynFieldHtml.js` with `scripts/sync-shared.js` (`npm run sync`), Node + Playwright
tests (`tests/*.js`, `test_*.js`).

**Spec:** `docs/superpowers/specs/2026-10-10-e2-adoption-design.md` at this plan's commit (read all of it first:
decisions 1-5, sections 5-9; this plan argues from it and cites its sections as "spec 6.1"). Background: `CLAUDE.md`
("Add-as-you-go lists", the `state.children` paragraph; "Shared code between the planners (marked regions)" including the
Windows CRLF gotcha; "Testing checklist"); `tests/child_dependents.js` and `test_children.js` (the boilerplate this plan
extends).

**Tasks:** Task 1 is the engine and normalization (shared `01-LIST_MAX`, US `hasChildAtMost`, tests); Task 2 is the UI
(shared `23-dynFieldHtml`, the field in both planners, copy, README, version badges, the Playwright check); Task 3 is
CLAUDE.md, the implementation record and the final gates. One commit per task.

1. **Typing a join year digit by digit** (`2`, `20`, `203`, `2032`): focus stays in the box (the list is not rebuilt), each
